# Spec Delta

## Purpose

Формирует для пользователя ленту карточек-кандидатов поблизости с учётом радиуса поиска, фильтров и статуса готовности, и принимает его решения свайпом.

## ADDED Requirements

### Requirement: Выдача кандидатов по радиусу поиска
Система ДОЛЖНА выдавать пользователю карточки других пользователей, чья сохранённая геопозиция находится в пределах заданного радиуса поиска от позиции пользователя.

#### Scenario: Кандидаты в радиусе
- **WHEN** пользователь открывает ленту с установленным радиусом поиска
- **THEN** система возвращает карточки кандидатов, находящихся в пределах этого радиуса, отсортированные по удалённости

#### Scenario: Нет кандидатов в радиусе
- **WHEN** в заданном радиусе нет подходящих кандидатов
- **THEN** система возвращает пустую ленту с сообщением о том, что никого не найдено, и предлагает увеличить радиус

#### Scenario: Изменение радиуса поиска
- **WHEN** пользователь изменяет значение радиуса поиска в допустимых границах
- **THEN** система пересчитывает выдачу ленты с учётом нового радиуса при следующем запросе

### Requirement: Фильтрация по полу и статусу готовности
Система ДОЛЖНА позволять фильтровать ленту по полу кандидата и по статусу готовности к встрече ("готов сейчас", "сегодня", "на этой неделе").

#### Scenario: Фильтр по полу
- **WHEN** пользователь задаёт фильтр по конкретному полу
- **THEN** лента содержит только кандидатов с выбранным полом в профиле

#### Scenario: Фильтр по статусу готовности
- **WHEN** пользователь выбирает фильтр "готов сейчас"
- **THEN** лента содержит только кандидатов, чей текущий статус готовности равен "готов сейчас"

### Requirement: Исключение уже просмотренных и заблокированных пользователей
Система ДОЛЖНА исключать из ленты пользователей, которых текущий пользователь уже оценил (лайк/дизлайк) недавно, а также пользователей, состоящих во взаимной блокировке с ним.

#### Scenario: Повторный показ после дизлайка
- **WHEN** пользователь поставил дизлайк кандидату
- **THEN** система не показывает этого кандидата повторно в ленте в течение установленного периода

#### Scenario: Заблокированный пользователь исключён из ленты
- **WHEN** между двумя пользователями установлена блокировка (в любую сторону)
- **THEN** ни один из них не видит другого в своей ленте

#### Scenario: Собственный профиль не показывается
- **WHEN** пользователь открывает ленту
- **THEN** система никогда не показывает ему его собственный профиль

### Requirement: Регистрация свайпа
Система ДОЛЖНА принимать и сохранять решение пользователя (лайк или дизлайк) по карточке кандидата.

#### Scenario: Сохранение лайка
- **WHEN** пользователь свайпает карточку кандидата вправо (лайк)
- **THEN** система сохраняет это решение и инициирует проверку на взаимный мэтч

#### Scenario: Сохранение дизлайка
- **WHEN** пользователь свайпает карточку кандидата влево (дизлайк)
- **THEN** система сохраняет это решение без инициирования мэтча

#### Scenario: Повторный свайп по уже оценённой карточке
- **WHEN** пользователь пытается повторно оценить кандидата, которого уже оценил ранее
- **THEN** система отклоняет повторную запись решения и возвращает текущее сохранённое решение
